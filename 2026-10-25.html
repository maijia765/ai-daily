要闻

AWS 开源 Infinity 智能体运行时：8GB 内存跑 7.5 万个并发 agent，等待时零算力

10 月 23 日，AWS 与 UC Berkeley 联合发布开源智能体运行时 Infinity（Apache 2.0，属 Hydro 项目）。它的核心设计是把工具调用当作挂起点：agent 发起工具调用后即挂起、只保留对话历史，等结果返回再恢复，类似编程语言里的无栈协程。官方称 8GB 内存可支撑 7.5 万个并发 agent，单个闲置 agent 仅占约 100KB 内存；还可跑在 Lambda + SQS + Aurora DSQL 的无服务器架构上，agent 等待期间不占用算力。Infinity 还内置 spawn_thread 与 report_to_parent 工具实现 agent 间通信，子线程默认处理事件，避免父 agent 的上下文窗口被工具输出撑爆。

需要注意的是，"7.5 万个 agent"这个数字要打折扣：实测是在服务器级 AMD EPYC 单线程、接模拟模型、每 agent 跑 20 轮对话的条件下完成的，"树莓派 5 能跑 7.5 万个"是按 100KB/个换算出来的，并非在树莓派上实测。真实 agent 的工具输出、文件内容和报错日志会比测试用的 1.2KB 对话历史重得多。

为什么重要： 长时运行的 agent 最大的成本不是推理，而是"干等"——等构建、等工具、等人工审批。Infinity 把"等待"从占着算力变成只占内存，解决的是 agent 规模化的经济账。如果这个模型成立，跑 1 万个常驻 agent 的成本结构会完全改变；但官方数字是模拟条件下的，落地前得按真实负载重新算账。

10 月 23 日，中国信通院人工智能研究所联合中国人工智能产业发展联盟发布《大模型词元服务性能监测报告（2026年）》。报告显示，词元服务呈现量价齐升：国内词元价格较去年下半年翻倍，量的增长达到 3 倍；2026 年 6 月，国内词元日均消耗量约 500 万亿，是 2025 年 12 月的近 4 倍。越来越多 MaaS 平台厂商通过公有云 API 方式供给大模型词元服务，而用户对词元服务性能缺乏直观判断依据、面临选型困难，是该报告开展的背景。
